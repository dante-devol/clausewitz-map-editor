# Deleting a state/region overwrites its file, never removes it

Deleting the last state (or strategic region) in a file leaves behind an emptied file on disk rather than deleting it, for the same reason a state/region save never deletes anything today: when the file being emptied is only shadowed from the game install (never yet copied into the mod folder), there's nothing to delete — the actual game file must never be touched, so the only correct move is writing an empty override into the mod folder, exactly like every other copy-on-write save already does via `resolveWriteTarget`. Applying the same "always overwrite, never delete" rule uniformly — even for a file that started out mod-owned — keeps deletion's file-handling identical in both cases instead of branching on where the file originally came from, at the cost of occasionally leaving an empty stub file in the user's mod folder.
